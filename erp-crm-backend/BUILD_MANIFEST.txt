                           CORE FEATURES
================================================================================

✅ Authentication & Authorization
   - JWT token-based auth
   - bcrypt password hashing (10 rounds)
   - Role-based access control (4 roles: ADMIN, SALES, WAREHOUSE, ACCOUNTS)
   - Login & register endpoints
   - Middleware-enforced on all protected routes

✅ Customer Management
   - Full CRUD operations
   - Pagination & filtering (status, type)
   - Full-text search (name, mobile, business)
   - Customer notes with audit trail
   - Follow-up date tracking

✅ Product & Inventory
   - Product CRUD with unique SKU
   - Stock level tracking with low-stock alerts
   - Stock movement history (auditable)
   - Atomic stock adjustments (IN/OUT)
   - Manual adjustment with reason logging

✅ Sales Challan (Core Business Logic)
   - Create DRAFT or CONFIRMED challans
   - Auto-generated sequential challan numbers (CH-YYYY-NNNN)
   - Product snapshot at creation time (immutable)
   - Stock validation before confirmation
   - Atomic stock deduction on confirmation
   - Atomic stock restoration on cancellation
   - Full transaction safety (all-or-nothing)

✅ Data Integrity & Concurrency
   - Atomic transactions for multi-step operations
   - Row-level locking prevents race conditions
   - Stock never goes negative (DB-level enforcement)
   - No partial updates on failures

✅ Error Handling
   - Centralized error middleware
   - Typed error classes for all scenarios
   - Field-level validation error messages
   - Insufficient stock errors with details
   - Consistent error response format

✅ API Design
   - RESTful endpoint design
   - Pagination support (page, limit, total)
   - Search & filter on all list endpoints
   - Consistent response shapes
   - Proper HTTP status codes (200, 201, 400, 401, 403, 404, 409, 500)

================================================================================
                        DATABASE SCHEMA
================================================================================

7 Models:
  1. User              — System users with roles
  2. Customer          — Business customers
  3. CustomerNote      — Follow-up notes & audit trail
  4. Product           — Inventory items
  5. StockMovement     — Stock transaction history
  6. Challan           — Sales/delivery orders
  7. ChallanItem       — Line items with snapshots

4 Enums:
  - Role               (ADMIN, SALES, WAREHOUSE, ACCOUNTS)
  - CustomerType       (RETAIL, WHOLESALE, DISTRIBUTOR)
  - CustomerStatus     (LEAD, ACTIVE, INACTIVE)
  - MovementType       (IN, OUT)
  - ChallanStatus      (DRAFT, CONFIRMED, CANCELLED)

Relationships:
  - User → many Challans, CustomerNotes, StockMovements (via createdBy)
  - Customer → many CustomerNotes, Challans
  - Challan → many ChallanItems
  - Product → many StockMovements, ChallanItems
  - ChallanItem → Product (reference for audit trail)

================================================================================
                           API ENDPOINTS
================================================================================

Authentication (2 endpoints):
  POST   /auth/login                    Login → JWT token
  POST   /auth/register                 Create user (admin-only)

Customers (5 endpoints):
  POST   /customers                     Create
  GET    /customers                     List (paginated, searchable)
  GET    /customers/:id                 Get detail
  PUT    /customers/:id                 Update
  POST   /customers/:id/notes           Add note

Products (6 endpoints):
  POST   /products                      Create
  GET    /products                      List (paginated, searchable)
  GET    /products/:id                  Get detail
  PUT    /products/:id                  Update
  GET    /products/:id/stock-log        Stock history
  POST   /products/:id/stock-adjust     Manual adjustment (atomic)

Challans (5 endpoints):
  POST   /challans                      Create (DRAFT or CONFIRMED)
  GET    /challans                      List (paginated, filterable)
  GET    /challans/:id                  Get detail
  PUT    /challans/:id/confirm          Confirm (stock check + deduct)
  PUT    /challans/:id/cancel           Cancel (restore stock)

Health (1 endpoint):
  GET    /health                        Health check

TOTAL: 19 documented endpoints (plus variants with query params = 25+)

                         NEXT STEPS
================================================================================

For Developers:
  1. Read QUICKSTART.md (5 min)
  2. Start server: npm run dev
  3. Test endpoints: open api.http in VS Code or import into Postman
  4. Read ARCHITECTURE.md to understand design
  5. Explore code: start with src/services/ for business logic

For Frontend Integration:
  1. Base URL: http://localhost:4000 (dev) or your production URL
  2. Auth: JWT in Authorization: Bearer <token> header
  3. Errors: Expect { error, message, details } on 4xx/5xx
  4. Pagination: Use page, limit query params; response includes total
  5. Validation: Map error.details.fields to form fields
  6. Insufficient Stock: Iterate error.details.details for per-item messages

For DevOps/Deployment:
  1. Build: npm run build
  2. Start: npm start (or use dist/index.js)
  3. DB: npm run db:migrate
  4. Seed (test env): npm run db:seed
  5. Env: Set DATABASE_URL, JWT_SECRET, PORT

For Database Administrators:
  1. Schema: Review prisma/schema.prisma
  2. Migrations: Applied via npm run db:migrate
  3. Indexes: Add per DATABASE.md recommendations
  4. Backup: Use pg_dump or cloud snapshots
  5. Monitoring: Set up slow query logs, connection monitoring
